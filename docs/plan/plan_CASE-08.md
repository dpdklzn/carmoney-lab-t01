## Проверка покрытия

Восемь REQ покрыты восемью задачами, AC-01..23 перечислены в соответствующих задачах. Сначала контракт/мок и валидация, затем независимые оценка/сверка/отказы, затем решение, HTTP и сохранение. Интеграционная приёмка каждой задачи входит в её AC, а не остаётся неучтённым «потом».

Метки: epic:case-08 и size:S / size:M / size:L. Если права аккаунта не позволяют создать или присвоить метки в командном репозитории, факт ограничения фиксируется, а требуемые метки остаются в теле issue до применения капитаном.

## Известные ограничения базы

- В командном main ещё нет исходного TEAM.md: он взят из открытого PR #1; капитан может сначала влить его. Дублирующий diff по TEAM.md исчезнет после включения исходного коммита в main.
- Мок сейчас описывает контракт, но не работающий сервис; задача REQ-01 не предполагает, что реализация уже существует.
- decisions.ltv сейчас NOT NULL; nullable LTV требует изменения хранения по REQ-08, без reset_db.
- API расширяется equipment; frontend вне scope эпика, текущая форма требует отдельной адаптации.
- Другой моделью эпик не проверялся; статическая проверка прослеживаемости не выдаётся за отчёт независимого агента-судьи.
