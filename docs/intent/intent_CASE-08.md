# Intent CASE-08: оценка залога по VIN

Статус: учебный вариант для эпика t01. Качественная основа — интервью 2026-10-13; недостающие параметры и дополнительные случаи заполнены по прямому поручению пользователя «Придумай все это сам». Это не реальные кредитные правила и не согласование корпоративного риск-менеджмента.

## Замысел

Получать по VIN характеристики и базовую цену из синтетического справочника, рассчитывать залоговую стоимость и использовать её в LTV. Сверять заявку со справочником; неподтверждённую оценку не заменять стоимостью заявки или приближённым числом. При невозможности оценки направлять заявку на ручную проверку.

Источник: docs/sources/CASE-08.md §1, П-1..П-6; интервью.

## Зачем

Связать решение с данными залога и различать большой LTV, расхождение данных и невозможность оценки. Предотвратить выдуманную стоимость при неизвестном VIN или сбое зависимости.

## Constraints

- Стоимость рассчитывается из данных справочника: B × (1 − dM − dA), округление half-up до целого рубля; LTV — сумма / эта стоимость в процентах с округлением до двух знаков. Источник: CASE-08 П-1/П-5, интервью.
- Пробег справочника 0..100000 / 100001..200000 / 200001..300000 / 300001..500000 км даёт скидку 0/5/10/15%; возраст 0..3 / 4..7 / 8..12 / 13..20 лет — 0/5/10/20%. Источник: CASE-08 П-1, SIM-REG-CASE08, DEC-08-01; новые синтетические значения по поручению пользователя.
- Данные заявки не определяют скидки; год и комплектация сверяются точно, абсолютная разница пробега до 10000 км включительно допустима. Источник: интервью, CASE-08 П-2, DEC-08-02.
- Расхождение переводит только approve в review. Review и reject по рассчитанному LTV не смягчаются; текущие общие пороги LTV не меняются. Источник: интервью, CASE-08 П-2/П-5, действующий командный код.
- Нет VIN → review с причиной «Нет данных по VIN в справочнике». Неполные/некорректные данные и ошибки зависимости → review с причиной «Данные справочника неполные или некорректные». Оценка и LTV отсутствуют, а не равны фиктивному нулю. Источник: интервью; CASE-08 П-3, DEC-08-03.
- Ответ справочника допускается только раньше 1500 мс; на границе и позже — review с причиной «Справочник не ответил вовремя», без оценки/LTV и автоматических повторов. Источник: интервью; CASE-08 П-4, DEC-08-04.
- Для API требуется комплектация; причины и nullable-оценка возвращаются и сохраняются. Ранее сохранённые записи не теряются. Ошибки заявки остаются ошибками ввода, а недоступность оценки не маскируется под успешно рассчитанную стоимость. Источник: CASE-08 П-6, DEC-08-05.

## Open questions

- OQ-CASE-08-01 закрыт учебным решением DEC-08-01: таблицы скидок и аддитивная формула заданы в CASE-08 П-1.
- OQ-CASE-08-02 закрыт DEC-08-02: допустимое абсолютное расхождение 10000 км включительно.
- OQ-CASE-08-03 закрыт DEC-08-04: таймаут 1500 мс; ровно на границе — таймаут.
- OQ-CASE-08-04 закрыт DEC-08-03: некорректные/неполные ответы не дают оценки, возвращается review.
- Расхождения SIM-REG/SIM-TICKET/SIM-DATA закрыты для этого синтетического варианта решениями DEC-08-01..05. Источник: разрешение пользователя самостоятельно заполнить кейс; это не скрытый выбор корпоративного документа.
- Открытых бизнес-вопросов, блокирующих учебную spec, нет. Технический способ хранения, миграции и организации мока определяется при реализации в рамках наблюдаемого поведения.

## Не входит

- Реальный внешней справочник, реальные заявки, VIN владельцев, персональные данные и реальные корпоративные тарифы.
- Приближённые оценки, fallback на стоимость заявки и автоматические повторы.
- Изменение общих порогов LTV и ранее действовавших проверок заявки, кроме явно добавленной комплектации.
- Новый дизайн, изменение frontend и автоматическое утверждение решений риск-менеджером. Эпик ограничен сервисом и API; текущая форма без поля комплектации потребует отдельной адаптации и не является критерием приёмки этого эпика.

Источник не-целей: CASE-08, интервью и учебная граница scope, зафиксированная по поручению постановщика.
